# 结论

DeepSeek 作答分析已从内部仍依赖百分制的 `ScoreResult`，完整迁移到 `interview.evidence-review.v1`。产品不再生成、展示或保存总分与五维分数。

# 输入边界

每次由用户点击“DeepSeek 证据审阅”后，本机桥接只发送当前岗位的公司、岗位、稳定 target key、JD 原文、简历正文、题目类别与来源片段，以及用户本轮回答。面经原题只附带当前题目关联的面经来源。

API Key 仍只存在于本机服务内存或环境变量，不进入浏览器存储与导出备份。

# 输出协议

页面固定展示已呈现的证据、尚未说明的事实、表达问题、判断与策略风险、与 JD 的关联、一个优先改进项、下一条追问，以及每条判断的材料来源和审阅边界。

# 真实性门槛

- 每条观察必须引用 source ledger 中已有的材料 ID；
- 所有来源必须属于当前 company + role target key；
- JD 关联必须同时引用 JD 与候选人材料或回答；
- 模型给出的直接引文必须逐字存在于对应 JD、简历、面经片段或回答；
- 任一协议校验失败时，整次结果不展示，用户可重试；
- 旧版 `score` 在 V5 本地数据迁移中丢弃，不伪装为新协议结果。

# 验证

- TypeScript 检查通过；
- 8 个测试文件、57 项测试通过；
- 正式构建通过；
- 构建仅保留既有的大体积 PDF 解析包提示，不影响本模块。

# 交互与输出完整性修复

- 将 DeepSeek 输出上限从 1,800 tokens 提升到 4,000 tokens，避免证据协议的多段结构被截断；
- 允许从 JSON 代码块或前后少量说明中安全提取最外层 JSON 对象；
- 作答卡按钮旁新增审阅中状态、就地错误信息和“重新审阅”按钮，错误不再只出现在页面顶部；
- 使用脱敏材料通过真实本地接口验证，返回 HTTP 200 且完整通过来源协议和逐字引文校验。
