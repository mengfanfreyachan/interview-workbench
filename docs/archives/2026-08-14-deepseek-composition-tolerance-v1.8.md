# DeepSeek 智能组题引文归一化与单题容错 V1.8

## 本模块解决的问题

DeepSeek 智能组题原先要求 `quote` 与来源逐字一致。模型只改变全半角、换行、空格或常见标点，就会使一题校验失败，并进一步让整批题目全部丢失。用户只能看到笼统错误，已通过校验的题目也无法保留。

## 已确认的产品决策

- 来源 ID、公司岗位归属、题目类别和真题身份继续严格校验，不因文本容错而放宽。
- 引文核验仅执行 Unicode NFKC、空白移除和有限中英文标点移除；不做同义词替换、模糊相似度、分词召回或模型二次判断。
- 一道衍生题的所有来源共同过闸。任一来源 ID 或引文无效时，整道题跳过，不部分接受来源。
- 无效或重复候选题 ID、模型伪装面经原题、无效来源、无法核验引文、缺少来源、简历题未引用简历等问题均按题处理。
- 只要至少一题有效，服务端就返回有效题目和安全 `warnings`；只有最终零题可用时才整批失败。
- `interview.evidence-review.v1` 作答审阅协议不在本次范围内，仍保持原有严格来源校验。

## 数据与交互变化

- `interview.question-composition.v1` 成功响应增加 `warnings`，每项只包含范围、原始位置、错误代码和安全说明，不包含 JD、简历或面经正文。
- 页面在成功组题后显示有效题数和安全跳过数量；现有有效题目正常进入题库。
- 全部题目不可用时提示用户重试或改用本地规则组题，原有题库不会被覆盖。
- 存储结构和工作台 V6 备份格式不变；警告属于页面临时状态，不进入 localStorage 或 JSON 备份。

## 安全边界

- 归一化只消除表现层差异，来源内容字符仍须按顺序连续存在，避免把相似语义误当原文证据。
- 来源 ID 不做模糊匹配；跨岗位来源仍在请求输入校验阶段被拒绝。
- 模型衍生题始终为 `coach_generated`，不能通过容错伪装为 `source_question`。
- 服务端警告不回传上游响应正文、API Key 或用户材料。

## 验证范围

- 覆盖 Unicode NFKC、全角空格、普通空白和中英文标点差异。
- 覆盖有效题与伪装真题、虚假引文、未知候选题和重复候选题混合返回时的部分成功。
- 覆盖全部题目不可用时的整批失败。
- 覆盖无警告成功响应和既有真题逐字保留行为。
- `npm run check` 通过。
- 12 个测试文件、88 项测试通过。
- `npm run build` 通过；保留既有 PDF.js 大 chunk 警告。

## 与 V1.7 相比

- V1.7 修复“正文已读取但无法提取真题”的本地采集管线。
- V1.8 修复“引文表现差异导致整批智能组题失败”的模型输出校验管线。
- 两者都遵循同一原则：明确区分阶段状态，保留可验证结果，不把失败静默伪装为成功。
