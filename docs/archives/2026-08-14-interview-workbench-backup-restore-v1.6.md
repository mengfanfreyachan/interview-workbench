# 面试工作台完整备份恢复与存储边界 V1.6

## 本模块解决的问题

此前工作台能够导出 JSON，但没有完整恢复入口；同时 `App.tsx` 直接读取、写入和清除 localStorage，浏览器存储失败时缺少统一错误边界。由于 JD、简历、面经、题库和训练历史只保存在当前浏览器，这会直接影响迁移和灾难恢复。

## 已确认的产品决策

- 继续使用本地优先的 Vite 单体，不引入数据库、账号、Redux、队列或新运行服务。
- 备份恢复采用“内存解析与迁移 → 内容预览 → 用户确认 → 完整替换”。
- 当前 MVP 不做跨备份自动合并，避免来源、题库和训练记录产生难以解释的冲突。
- V1–V6 继续复用 `restoreWorkbenchState` 做兼容迁移，不改变 V6 字段含义。
- 新导出使用持久字段白名单；DeepSeek Key、采集状态、请求状态和页面临时状态不进入备份。
- localStorage 写入失败时不更新内存工作台，也不显示恢复成功。

## 核心用户流程

1. 用户点击右上角“导入备份”并选择 JSON。
2. 页面在内存中检查文件大小、JSON 格式和工作台必要字段，再执行旧版本迁移。
3. 页面展示文件名、公司岗位数、面经来源数、当前题库数、简历字数和训练记录数；如有旧数据隔离、历史索引重建或旧机械题库清理，也一并说明。
4. 用户确认后，系统先写入 localStorage；写入成功后才替换页面状态。
5. DeepSeek Key 不从备份恢复，新环境需要重新配置。

## 代码与数据边界

- `src/workbench-backup.ts`：备份字段白名单、序列化、10 MB 上限、解析、迁移和预览摘要。
- `src/workbench-repository.ts`：当前及 V1–V5 旧存储键的统一读取、V6 保存与完整清除。
- `src/App.tsx`：只负责触发导入、展示预览和确认；不再自行拼装 localStorage 数据格式。
- 存储键保持 `xiangqian.interview-workbench.v6`。
- `experienceLibraries` 仍是可重建索引；`questions` 仍是当前岗位可重新生成的缓存；`trainingSessions` 仍是长期保留成果。

## 安全与失败行为

- 空文件、损坏 JSON、缺少必要字段和超大文件在写入前拒绝。
- 导入失败或用户取消时，当前内存状态和浏览器数据均不改变。
- 浏览器初始读取失败时停止自动保存，避免脱敏样例覆盖原有损坏数据；用户可通过有效备份恢复或明确清除后重新启用保存。
- 清除操作只删除当前工作台及其 V1–V5 旧键，不触碰其他浏览器数据。
