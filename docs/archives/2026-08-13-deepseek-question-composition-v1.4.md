# DeepSeek 来源约束智能组题 V1.4

## 解决的问题

在保留确定性本地组题的同时，让用户可主动调用 DeepSeek 对当前岗位材料做深度精选和组题，并确保模型生成内容不能冒充外部面经真题。

## 已确认决策

- 主类别仍只有 `resume_deep_dive` 与 `role_capability`；题库筛选为“全部｜简历题｜专业 / JD 题｜面经真题”，其中面经真题是 `source_question` 来源维度。
- 本地规则组题继续可独立使用；DeepSeek 智能组题是单独的用户主动操作，复用现有进程内会话 Key 或环境 Key。
- 服务端输入只接受当前目标、JD、简历、本地候选题及当前岗位面经来源，最多输出 12 题。
- 模型只能选择合法候选题，或基于来源账本衍生新题。选择的 `source_question` 保持原题原文和来源；所有衍生题强制为 `coach_generated`。
- 服务端校验题型、数量、候选题 ID、目标隔离、来源 ID 和逐字引文；跨岗位来源、虚构引文、无来源题及冒充真题的模型结果整次拒绝。

## 交互与错误

- 生成区并列提供“本地规则组题”和“DeepSeek 智能组题”。
- 组题中显示就地状态；超时、网络、上游配置、限流及输出协议错误均使用不包含上游正文的安全提示，失败时保留现有题库。
- 题卡明确显示“面经原题”“本地规则生成”或“DeepSeek 生成”，真题继续显示平台、标题和材料引用。

## 验证

- TypeScript 检查通过。
- 9 个测试文件、72 项测试通过，覆盖岗位隔离、候选题与来源校验、真题原文保留、衍生题 provenance、虚假引文和真题冒充拒绝。
- 未真实调用 DeepSeek；所有模型响应均由本地测试模拟。
