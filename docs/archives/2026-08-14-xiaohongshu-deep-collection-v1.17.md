# 小红书深度采集 V1.17

## 目标

把“单次搜索、最多读取前三篇”的有限代搜升级为用户主动触发的深度采集：自动执行多组相关查询，跨轮和跨批次增量去重，在结果趋于饱和时停止，并向用户解释本轮实际覆盖。

## 已确认产品规则

- “穷尽”定义为受限查询计划内达到搜索饱和，不承诺覆盖私密、删除、登录不可见或平台未返回的内容。
- 每次点击最多执行 6 组公司内查询；起始词可编辑，后续自动覆盖精确岗位、岗位族、面试、面试题和面试轮次。
- 至少执行 4 轮后，连续 2 轮没有新增唯一来源即停止；达到 20 篇新来源、约 6 分钟总时限或查询计划结束也会停止。
- 不跨公司搜索，不建立数据库、队列或新服务，不转为后台无人值守抓取。

## 数据与采集边界

- 浏览器把当前岗位已有来源 URL 一并发送给本机桥接；桥接按小红书笔记 ID 统一 `/explore/` 与 `/search_result/` 等路径，跳过已有来源。
- 查询轮次之间和正文读取之间保持串行间隔；正文只读取新候选，单篇失败不清空已成功来源。
- 带 `xsec_token` 的临时 URL 只用于本机当次读取；返回页面和持久化前继续清除参数与片段。
- 持久化仍只保存标题、平台、脱敏 URL、采集时间、最多 320 字摘要和提取出的题目，不保存完整正文或 Cookie。

## 覆盖报告

最终结果展示：计划／执行查询数、累计命中、唯一来源、已有跳过、新增读取、含真题来源、提取真题数、读取失败和停止原因。用户可以展开每轮查询，查看该词命中数和新增唯一来源数。

正文读取成功但自动提取为零时，页面使用“已保存正文摘要，自动提取 0 道”，并说明正文中仍可能存在面试信息，避免把规则未识别误解为原文没有题目。

## 兼容性

API 继续使用 `agent-reach.interview-experience.v1` 的来源字段；新增 `coverage` 和扩展统计字段均为向后兼容字段。旧 JSON 导入和不含覆盖字段的模拟响应仍可读取。

## 验证

- 纯策略测试覆盖查询矩阵、顺序、去重和 6 轮上限。
- 桥接测试覆盖多查询、跨轮去重、已有来源跳过、饱和停止、部分正文失败及零题摘要。
- 页面回归覆盖 20 篇请求上限、已有 URL 增量参数、深度采集中状态、饱和原因、逐轮覆盖和来源归档。
- 1280px 桌面实际页面无横向溢出；材料区、采集按钮和长说明保持稳定。
- 类型检查、16 个测试文件共 117 项测试、6 条页面专项回归和正式构建全部通过；构建只有既有 PDF.js 大 chunk 警告。

## 后续

2026-08-18 已完成首个真实岗位“字节跳动 · 法务”受控观察：4 组查询累计发现 19 个唯一来源，成功读取 16 篇，其中 11 篇提取 51 道真题，3 篇正文失败；页面观察耗时约 6 分 18 秒。完整脱敏记录见 `docs/observations/2026-08-18-xiaohongshu-deep-collection-byte-legal-v1.md`。

该轮也证明当前“查询计划执行完”不等于搜索饱和：前三组分别失败、零命中、超时，全部 19 个来源来自最后一组，之后没有补充查询验证新增是否趋近于零。下一步先将搜索失败与正文失败分开统计，把停止文案改为“已尝试全部搜索词”，并保证高产查询之后仍有受限的饱和检查，再进行第二个真实岗位观察。当前不新增后台任务系统。
