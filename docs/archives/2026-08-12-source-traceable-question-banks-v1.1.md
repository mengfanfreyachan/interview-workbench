# 四类来源化题库 V1.1（已由 V1.2 收敛）

> 该归档记录历史四类实现。当前版本已将主类别收敛为“简历题”和“专业 / JD 题”；`jd_resume_connection` 与 `experience_original` 不再是独立类别。旧缓存会在恢复时迁移：结合题归入专业 / JD，面经原题归入专业 / JD 并保留 `source_question` 来源标签。

## 模块目标

把原来的“简历题＋岗位通用题”改为由当前 JD、当前简历和当前岗位面经共同驱动的四类题库，避免无依据的岗位推演，并让用户知道每道题为什么出现。

## 四类题库

1. `jd_capability`：从 JD 要求原文生成，验证岗位理解、方法、约束和验证方式。
2. `resume_deep_dive`：从简历中的行动或结果主张生成，核对目标、责任边界、行动和结果依据。
3. `jd_resume_connection`：同时引用一条 JD 要求和一条简历主张，要求用户说明已有证据和仍未覆盖的部分。
4. `experience_original`：保留用户导入或 Agent Reach 面经中的原题，展示平台、标题和具体来源。

## 来源协议

- `source_question` 只用于忠实保留的面经题。
- `source_derived` 用于基于 JD、简历或二者生成的问题。
- 每道新题使用 `sourceRefs` 保存来源类型、来源 ID、标签、定位和短摘录。
- 面经原题继续保存 `sourceId`，用于关联原帖 URL 和平台信息。
- 旧题没有 `category` 时继续兼容显示：旧简历题进入简历深挖区，旧岗位题进入面经原题区，但重新生成后全部使用 V1.1 分类。

## 生成边界

- 没有 JD 时不生成 JD 能力题和 JD × 简历结合题，也不使用岗位名称假装成 JD 内容。
- 简历主张优先选择包含行动、结果、数据或协作信号的经历段，过滤联系方式和纯教育信息。
- 结合题必须同时包含 `jd` 和 `resume` 两类引用。
- 面经只读取当前 target key 的来源；未归类和其他岗位资料不进入题库。
- 本地规则最多生成 3 道 JD 题、3 道简历题、3 道结合题和 6 道面经原题，保持 MVP 可练习范围。

## 页面变化

- 题库区改为四张独立卡片，每题显示“材料原题”或“基于材料生成”。
- 材料引用显示来源标签、定位和短摘录。
- 作答区同步显示当前题目分类和材料来源。
- 材料不足的分类保留空状态，不制造题目填满页面。

## 验证

- TypeScript 检查通过。
- 56 个自动测试通过，覆盖四类生成、缺 JD 不造题、双来源结合题、简历锚点筛选、超长单行解析文本、面经原题和跨岗位隔离。
- 生产构建通过。

## 当前边界

- 本模块使用确定性本地抽取生成问题，不调用模型做 JD 语义拆解。
- DeepSeek 回答分析仍使用旧接口，尚未读取 JD 与 `sourceRefs`；下一模块将迁移到 `interview.evidence-review.v1`。
