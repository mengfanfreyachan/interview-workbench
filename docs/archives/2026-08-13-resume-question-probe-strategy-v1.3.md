# 简历深挖题生成策略 V1.3

## 解决的问题

旧版简历题把每条经历都套进“目标、具体责任和结果依据分别是什么”，导致题目机械、堆叠问项，也会误选职位标题行。

## 已确认决策

- 从简历中按行动、结果和量化信号排序，最多选择 1–3 条高价值主张；职位／日期标题行不作为主张。
- 每条主张只选择一个 `primaryProbe`：个人贡献、关键决策、指标口径、约束下执行、取舍复盘或反事实判断。
- 有明确成果指标时优先追指标定义；过程数量、时间或范围数字不自动视为结果指标。
- JD 相关性只依据确定性词项交集标记为 `jd_aligned`，无 JD 或无交集标记 `general_signal`，不声称匹配。
- `sourceRefs[].excerpt` 保留简历逐字引文；题目使用短锚点，完整原文在来源区展示。
- `cues` 作为后续追问元数据，不在首次作答前展示答题清单。

## 数据兼容

`Question.primaryProbe` 与 `Question.jdRelevance` 为可选字段。普通旧缓存恢复时，简历题补 `personal_contribution` 和 `general_signal`，保留已有 `sourceRefs`。若检测到“三项分别回答”或“任选一段经历”等旧通用模板，则只清空当前生成题库并提示重新生成；JD、简历、面经和已完成训练记录均保留。

## 验证

- 覆盖数字成果、个人贡献、方法／决策与标题行过滤。
- 覆盖无 JD 的一般经历标记、最多 3 条、来源逐字 excerpt 和旧缓存恢复。
- 增加 `buildResumeQuestions` 黑盒测试入口：中文能力锚点参与排序，JD 相关主张优先于无关高分主张；职位／日期标题被过滤；“5 轮追问”等过程数量不会触发成果指标题；每个标题严格只有一个问项。
- 未调用 DeepSeek 或其他外部服务。

## 尚未完成

- 真实用户简历仍需人工观察不同岗位下的主张切分质量；本次只建立确定性本地规则。
