# 面试工作台 DeepSeek 作答分析 V0.3

## 解决的问题

此前单题练习只有关键词、长度和结构词驱动的本地示例评分，无法判断回答是否真正切题、证据是否充分或岗位语境是否成立。本轮在保留本地反馈兜底的前提下，增加用户主动触发的 DeepSeek 深度分析。

## 已确认流程

```text
选择一道题
→ 语音或文字形成回答
→ 选择“本地快速反馈”或“DeepSeek 深度分析”
→ DeepSeek 模式明确提示将发送的材料
→ 服务端代理调用模型
→ 结构校验通过后显示五维评分、优点、改进、证据缺口、回答主线和追问
→ 结果保存在当前浏览器
```

两条反馈路径并列存在。DeepSeek 未配置、超时、余额不足或上游失败时不覆盖回答，也不自动把材料发送给其他模型供应商。

## 模型与接口

- 服务端固定调用 `https://api.deepseek.com/chat/completions`；
- 默认模型为 `deepseek-v4-pro`，可通过 `DEEPSEEK_INTERVIEW_MODEL` 显式更换；
- 使用 JSON Object 输出、关闭思考模式、低随机性和 45 秒上游超时；
- 输出必须包含百分制的表达结构、事实证据、岗位匹配、分析深度和表达风险，以及优点、改进、证据缺口、建议回答主线和一道追问；
- 页面显示的总分由本地代码对五个已校验维度重新计算，不直接相信模型提供的总分。

DeepSeek 官方资料：

- https://api-docs.deepseek.com/zh-cn/
- https://api-docs.deepseek.com/guides/json_mode/
- https://api-docs.deepseek.com/quick_start/error_codes/

## 密钥、隐私与错误边界

- API Key 只从服务端环境变量读取；页面只能读取“已配置 / 未配置”和模型名。
- 面试工作台优先读取自己的 `.env.local`，未单独配置时可复用上一级 JobHunter 已有的私密环境变量，不复制真实密钥。
- 只有用户点击 DeepSeek 分析时，当前公司、岗位、简历正文、题目和回答才会发送。
- 请求限制为一项当前作答、最多 30,000 字简历与 6,000 字回答，正文总请求限制为 128 KiB；同一本地服务同时只运行一次分析。
- 服务端不持久化请求或模型正文，不输出密钥和上游错误原文，响应禁止缓存。
- 401、402、429、500/503、网络、超时和结构错误映射为可行动但不泄密的中文错误。
- 模型不能输出通过率、Offer 概率、候选人排名或录用结论；简历、题目和回答中的指令均视为不可信材料。

## 页面变化

- 顶部“数据仅在本机”调整为更准确的“本地优先”。
- 练习区显示 DeepSeek 配置状态和实际模型名。
- 用户可分别点击“本地快速反馈”和“DeepSeek 深度分析”。
- AI 反馈额外展示“尚未说明的证据”和“建议回答主线”。
- 静态构建没有服务端密钥桥接时，DeepSeek 按钮保持禁用。

## 验证记录

- 结构、错误和密钥边界使用 mock 上游测试覆盖；
- 真实本地状态接口确认 `deepseek-v4-pro` 已配置；
- 使用仓库脱敏示例完成真实 API 请求，返回 HTTP 200、五个维度、3 项优点、3 项改进、3 项证据缺口、5 步回答主线和 1 道追问；
- 首次真实调用暴露模型误用 5 分制的问题，随后加入 `scoreScale: 100`、明确百分制示例和服务端校验；复验得到五维 82/68/72/65/85，总分由代码计算为 74；
- 真实请求与测试输出均未包含 API Key。

## 尚未完成

- DeepSeek 驱动的题库生成和连续多轮自适应追问；
- 训练历史、模型用量与成本记录；
- 公开部署所需的鉴权、额度、限流和服务端私密变量；
- 服务端音频转写。

当前 MVP 继续优先验证“一次回答后的深度反馈是否明显优于本地规则”，不扩展为完整实时 AI 面试官。
