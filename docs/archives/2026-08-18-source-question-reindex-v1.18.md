# 来源真题重新索引 V1.18

## 解决的问题

旧来源可能已经保存正文摘要，但 `questions` 仍为空。解析器规则升级后，这些记录不会自动重算；再次深度采集又会按已有 URL 跳过，导致用户在整理正文中能看到真实题目，来源卡片却继续显示 0 道。多个标签页同时打开时，各页 React 内存状态也可能不同步。

## 已确认产品规则

- 面试题解析继续使用本地确定性规则，不用 DeepSeek 替代来源原题识别。
- 完整小红书正文不进入浏览器持久化；长期保存范围仍是标题、平台、脱敏 URL、采集时间、最多 320 字摘要、题目和导入方式。
- 重新识别必须摘要优先。只有用户主动点击、摘要仍不足且来源是 Agent Reach 小红书链接时，才通过本机 OpenCLI 重读正文。
- 单次原文重读最多 10 篇，总时限约 3 分钟；不搜索新来源，不转为后台任务，不自动重试。
- 跨标签页变化只提示，不自动覆盖用户当前编辑内容。

## 数据与迁移

- `ExperienceSource` 新增可持久化的 `questionParserVersion`；当前 `interview-question-extractor` 版本为 2，旧记录使用 0 表示未版本化。
- 恢复 V1–V6 数据时，`questions: []` 且未使用当前版本解析的来源会对现有摘要重新提取；迁移结果报告重新检查来源数和恢复题数。
- 新版 Agent Reach 采集和原文重读响应都返回解析器版本。
- 备份格式继续使用 V6，新增字段向后兼容；导入预览会说明将重新检查多少旧来源、可恢复多少题。

## 富信息去重

- 有 URL 的来源按“目标岗位 + URL”识别重复项，不再把标题变化视为新来源。
- 无 URL 的来源按“目标岗位 + 标题”去重。
- 重复项优先采用题目更多、摘要更完整的记录，并合并去重后的题目。
- 合并结果保留最早记录的 `id`，确保已有题库、来源引用和训练记录不会断链。

## 用户流程

1. 页面加载时先对旧零题来源执行摘要回填，不联网。
2. 当前岗位仍有零题来源时，材料区显示待识别篇数和“重新识别真题”。
3. 点击后再次解析摘要；只把仍为零且具备可信小红书 URL 的来源发送到本机重读接口。
4. 成功与失败来源分别保留，页面说明摘要恢复题数、重读篇数、总恢复题数和失败篇数。
5. 其他标签页保存或清除工作台时，本页显示“加载最新数据／稍后”，由用户决定是否替换当前内存状态。

## 文案

- 旧：`已保存正文摘要，自动提取 0 道`
- 新：`已保存正文摘要，尚未识别到真题`

新文案只说明当前识别状态，不再暗示正文中不存在面试题。

- 单元测试覆盖解析器版本迁移、摘要回填、重复 URL 富信息合并和受限可信 URL 原文重读。
- 页面测试覆盖“摘要不足后用户触发原文重读”和“跨标签页先提示、确认后加载”。
- 16 个测试文件、123 项测试全部通过。
- TypeScript 检查和正式构建通过；仅保留既有 PDF.js 大 chunk 警告。
