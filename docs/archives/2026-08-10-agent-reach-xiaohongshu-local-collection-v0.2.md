# 面试工作台 Agent Reach 小红书本地采集 V0.2

## 解决的问题

用户可在独立面试工作台内基于目标公司和岗位形成可编辑搜索词，并通过一次明确点击采集少量小红书面经。采集结果保留公开来源、短摘录和保守抽取的明确问题，并直接加入现有面经库。

## 已确认流程与交互

流程固定为：用户切换到 Agent Reach 模式 → 检查或编辑搜索词 → 点击一次采集 → 本地开发服务器搜索一轮 → 串行读取最多 3 篇正文 → 页面显示采集中、成功数量和逐篇失败原因 → 成功来源加入面经库。再次采集必须由用户再次点击，不存在后台轮询或循环任务。

静态构建明确禁用采集按钮并显示“一键采集仅在本地 `npm run dev` 可用；静态部署需服务端 adapter”。手动粘贴、文本导入、Agent Reach JSON 导入、题库生成、语音和本地数据保持兼容。

## 数据与安全边界

- 开发服务器仅接受有限长度的 `query`、1 至 3 的正文读取数量，以及有限长度的公司和岗位文案。
- 进程以参数数组和 `shell: false` 调用固定的 OpenCLI 小红书只读命令，不接受任意命令或子命令。
- 链路固定为 `search` 后使用结果中的完整 URL 执行 `note`，禁止裸 note ID。
- 正文读取串行执行，两次读取间隔至少 2 秒；单次 OpenCLI 最长 30 秒、总体请求最长 90 秒，浏览器端 95 秒后终止等待。
- `xsec_token` 只用于服务端进程内即时正文读取；返回浏览器和保存来源前移除查询参数与片段。
- 不读取或保存浏览器 Cookie，不替用户登录，不执行评论、点赞、发布等写操作。
- 问题抽取使用确定性保守规则。没有明确问题时仅保留短摘录，不生成虚构题目。

## 已完成

- Vite 开发服务器受限 API 桥接和可注入进程执行器；
- OpenCLI 搜索结果与正文 `field/value` JSON 的兼容解析；
- 一键采集状态、成功数、失败原因和来源卡片；
- 采集结果合并到现有 `ExperienceSource` 面经库；
- 纯函数与 mock 进程测试；
- 使用当前 Chrome/OpenCLI 会话完成一次真实端到端联调：搜索“豆包 大模型 产品经理 面试”，成功读取 1 篇正文并保守抽取 12 道问题，返回的公开来源 URL 不含查询参数；
- README 中的本地与静态部署边界说明。

## 尚未完成

## 验证记录

- `npm run check`：通过；
- `npm test`：2 个测试文件、9 个测试通过；
- `npm run build`：通过；
- 本地开发 API：HTTP 200，1 个成功来源，0 个失败来源，12 道抽取问题；
- 首次以 15 秒单进程上限联调时搜索超时。实测同一搜索约需 14 秒，因此把单进程/总体/浏览器等待分别调整为 30/90/95 秒，仍保留有限采集边界。
