# 面试工作台：我的面经库 V0.6

## 模块目标

把已经按公司与岗位隔离的面经资料组织成一个本地历史目录。用户完成多个岗位的采集或整理后，可以看到以前的面经库并重新打开，而不是只能看到其他岗位资料的隔离数量。

## 用户流程

1. 用户通过 Agent Reach、文件／JSON 导入或手动粘贴准备当前岗位面经。
2. 成功采集／导入，或生成题库后，当前“公司 + 岗位”自动归档。
3. “我的面经库”显示公司、岗位、来源数、已提取问题数和更新时间。
4. 点击历史卡片后切换到该岗位，显示其已保存的正文与来源。
5. 题库仍只接受当前岗位来源；打开旧库后可重新生成。

## 数据和迁移

- 本地 schema 升级为 V3，存储键为 `xiangqian.interview-workbench.v3`。
- `ExperienceLibrary` 保存岗位目标、创建时间与最近更新时间。
- `experienceLibraries` 以标准化岗位 key 去重。
- V2 已归类来源与非空草稿自动派生历史条目；V1 未归类来源保持隔离。

## 边界

- 全部资料继续只保存在当前浏览器并随 JSON 备份导出。
- 打开历史库不触发联网；Agent Reach 与 DeepSeek 仍只在用户主动点击时调用。
- 当前不做改名、删除、搜索、账号同步、跨设备同步或历史题库版本管理。

## 验证

- TypeScript 检查通过。
- 7 个测试文件、41 项测试通过。
- 已覆盖历史条目去重更新时间、V2 自动迁移、V3 时间保留和未归类来源忽略。

## 与 V0.5 的关系

V0.5 建立岗位级来源隔离；V0.6 只增加历史目录与重新进入能力，不改变隔离和题库生成边界。
