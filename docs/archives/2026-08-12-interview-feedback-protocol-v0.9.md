# 面试回答反馈协议 V0.9

## 本次结论

- 模拟面试不把回答质量压缩成一个总分。分数可以在内部保留以兼容旧数据，但页面不再展示百分制结果，也不使用它推断通过率、录用概率或候选人排名。
- 反馈主结构改为“回答审阅”：关键观察、已呈现的证据、尚未说明的证据、下一轮可执行改进、建议追问。
- 评价必须区分“回答没有说明”与“候选人没有经历”，不得因为简历中没有一段文字就断言候选人没有该经历。
- 评价必须同时读取目标公司、目标岗位、当前题目、简历正文和本次回答；不能只按通用表达模板评价。

## 建议的独立 Skill 边界

建议建立一个独立的面试 Skill，但先固化评价协议，再把协议接入页面。Skill 的首期职责为：

1. 从 JD 提炼该岗位本轮要验证的能力和业务结果。
2. 从简历提取可被追问的经历证据，并标出证据出处。
3. 生成简历深挖题、岗位专业题和针对性追问，避免只生成通用题。
4. 对回答做证据审阅：事实、个人动作、结果口径、判断依据、岗位关联、风险与遗漏。
5. 给出下一轮可执行的回答改进和一条最有价值的追问。

## 暂不纳入

- 录用预测、通过率、候选人排名。
- 仅凭语言流畅度推断能力。
- 没有 JD 或简历依据的“岗位匹配”结论。
- 把 AI 的主观判断写成确定事实。

## 页面实现

V0.9 已将右侧反馈从分数卡改为“回答审阅”卡片，并放大辅助文字。`ScoreResult` 暂时保留分数字段以兼容本地旧数据和 DeepSeek 返回协议，后续 Skill 接入时再评估是否迁移为结构化 `EvidenceReview`。

## V1 网页协议

- 已定义协议版本 `interview.evidence-review.v1`，完整说明见 `docs/INTERVIEW_EVIDENCE_REVIEW_V1.md`。
- 已建立 TypeScript 类型与运行时校验器 `src/interview-review-protocol.ts`。
- 八个页面区块固定为：已呈现的证据、尚未说明的事实、表达问题、判断与策略风险、与 JD 的关联、优先改进项、下一条追问、材料来源。
- 所有事实观察必须引用来源；JD 关联必须同时引用 JD 与候选人材料或回答。
- 当前只完成协议层，不在本模块内替换 DeepSeek 请求、页面状态或本地存储。

## 验证

- TypeScript 检查通过。
- 协议测试覆盖合法结果、无来源判断、跨岗位污染、JD 单边引用和无效观察关联。
