# 小红书连续编号真题提取与采集统计 V1.7

## 本模块解决的问题

OpenCLI 已能读取小红书正文，但旧规则主要依赖换行、问号和疑问词。正文使用连续 `1⃣️…2⃣️…`、星标数字或无问号短题时，来源会被保存但真题栏为空；页面又只显示“成功 N 篇”，无法区分搜索、正文读取和题目提取。

## 已确认的产品决策

- 真题提取保持确定性纯规则，不把正文交给模型，不新增后台调用。
- 支持 `1⃣️`、`1️⃣`、`①`、`一、`、普通数字和 `🌟1.` 等编号。
- 支持“自我介绍”“谈实习经历”“岗位理解”“反问”等无问号面试提示。
- 提取结果保留原文题目主体；允许去除编号和明确的作者解释括号，但不补写问号、不改写题意。
- 流程说明、备考建议和普通叙述保持保守过滤；宁可保存正文后标记零真题，也不把建议伪装成面试原题。
- 搜索命中、正文读取、真题提取和读取失败必须分别统计。

## 代码与数据变化

- 新增 `src/interview-question-extractor.ts`，采集桥接只负责调用该纯模块。
- Agent Reach 响应增加 `stats`：`searchHitCount`、`bodyReadCount`、`questionCount`、`failureCount`。
- 页面采集结果展示四项统计，不再使用含义模糊的“本次成功 N 篇”。
- 每个来源显示“已提取 N 道真题”或“正文已读取，未识别到真题”。
- 来源结构和工作台 V6 存储含义不变；题库仍只从 `questions` 非空的来源创建 `source_question`。

## 真实 E2E 观察

2026-08-14 使用“字节跳动 法务 面经”执行受控本地采集：每次只搜索一轮，最多串行读取 3 篇，沿用 2 秒间隔。

- OpenCLI 搜索返回 20 条可解析命中；桥接只读取请求限定的 1–3 篇。
- 星标数字文章在服务重启后成功提取出自我介绍、加入原因、通勤地址、实习挑战和全勤课程等题目，证明正文读取到真题提取链路恢复。
- E2E 同时暴露作者解释括号和备考建议误收；已将真实形态固化为回归测试，并增加题目主体截取和建议过滤。
- 最终一次随机首篇为非题目型经验文章，结果为搜索命中 20、正文读取 1、真题 0、失败 0，零真题状态正确保留且未伪造问题。
- 完整临时 URL 只用于 OpenCLI 当次读取；响应与保存数据不含 `xsec_token`。
