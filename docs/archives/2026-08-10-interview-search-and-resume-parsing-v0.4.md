# 面试工作台搜索策略与简历解析 V0.4

## 解决的问题

精确岗位名在小红书上可能没有同名面经，用户此前只能手动重写搜索词；简历入口也只能读取文本文件，无法直接使用常见的 Word 和 PDF 简历。

## 已确认流程

```text
填写公司和岗位
→ 选择精确搜索或模糊搜索
→ 核对并可编辑实际搜索词
→ 用户点击一次后执行一次有限采集

上传 TXT / Markdown / DOCX / 文字型 PDF
→ 浏览器本地解析
→ 转成可编辑文本
→ 用户核对后生成题库
→ 只有主动点击 DeepSeek 时才发送解析后的正文
```

## 规则与边界

- 精确搜索保留公司和完整岗位名；
- 模糊搜索保持公司不变，只移除岗位噪声并归入确定性的岗位族；
- 当前不跨公司、不自动发起多轮检索，最终搜索词始终可见和可编辑；
- DOCX 通过 Mammoth 抽取原始文字，不渲染文档 HTML；
- PDF 通过 PDF.js 读取文本层；扫描件、图片型 PDF、加密 PDF 和旧版 DOC 暂不支持；
- 原文件不上传，解析后的文本继续沿用现有本地存储、导出和清除能力；
- 单文件上限 15 MB，解析后正文上限 30,000 字。

## 验证

- TypeScript、29 项测试和生产构建通过；
- 脱敏临时 DOCX / PDF 实际解析验证通过；
- 真实模糊搜索“字节跳动 AI 产品经理 面经”命中相关小红书来源；
- 本地开发服务继续运行于 `http://127.0.0.1:4173/`。

## 未包含

- OCR；
- 简历教育 / 经历 / 技能字段的语义结构化；
- 跨公司扩搜与自动回退；
- 双栏和复杂表格版面重建。
