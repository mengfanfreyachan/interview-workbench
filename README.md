# 面试工作台 MVP

> 跨 AI 或跨机器迁移请先阅读 [`HANDOFF.md`](./HANDOFF.md)；文件复制清单见 [`MIGRATION_MANIFEST.txt`](./MIGRATION_MANIFEST.txt)。

一个与 JobHunter 主应用运行时代码隔离的 Vite / React / TypeScript 前端原型。它延续独立投递台的本地优先视觉和数据边界，用一页完成“目标岗位 → JD / 面经 / 简历 → 两类主题题库与来源标签 → 单题作答 → DeepSeek 证据审阅”。

## 开源本地运行

要求 Node.js 22 或更高版本。下载或克隆项目后，在本目录运行：

```bash
cd interview-workbench
npm install
npm run dev
```

浏览器打开终端显示的本机地址，默认是 `http://localhost:4173`。本项目面向单用户本机运行，不需要账号、数据库或云端部署。

### 可选能力

- **不配置任何外部能力也能使用：**JD、简历和面经的手动输入／文件导入、本地简历解析、本地规则组题、题库筛选、JSON 备份与恢复均可正常使用。
- **DeepSeek（可选）：**智能组题和证据审阅需要使用者自己的 DeepSeek API Key。可在页面中临时填写，Key 只保存在当前本机服务的内存中，服务停止后失效；也可使用不提交 Git 的 `.env.local`。
- **Agent Reach / OpenCLI（可选）：**小红书面经深度采集需要本机安装并连接 OpenCLI、保持 Chrome 可用，并由使用者自行登录对应平台。没有 OpenCLI 时仍可手动粘贴面经或导入已有 JSON。

### 本地数据与卸载

工作台数据保存在运行该地址的浏览器 `localStorage` 中，存储键为 `xiangqian.interview-workbench.v6`；代码目录、`npm install` 和 Git 不包含这些用户数据。更换电脑、浏览器、端口，或清理网站数据、卸载项目前，请先点击页面右上角的“导出”保存 JSON。新环境启动后点击“导入备份”，预览内容并确认完整恢复。DeepSeek Key 不进入备份，需要在新环境重新配置。

## 验证

```bash
npm run check
npm test
npm run test:ui
npm run build
```

页面级测试使用 Vitest、jsdom、React Testing Library 和 user-event；`npm run test:ui` 可只运行用户核心流程，`npm test` 仍运行全部纯函数、桥接和页面测试。

当前十条页面级核心回归覆盖：备份预览与确认恢复、岗位切换隔离、采集四阶段状态、采集失败提示、本地来源化组题、DeepSeek 单题容错、页面会话 Key 配置、有界两轮训练、来源原文重读重新识别、跨标签页确认刷新。产品、运营、法务三套脱敏组题 Golden Cases 进一步固定两类题库、逐字引文、岗位相关经历、追问切口、原题保真、跨岗位隔离、去重与单一问题边界。Golden 自动门禁使用确定性本地引擎；DeepSeek 页面回归模拟已经由服务端完成单题校验后的契约，不依赖真实 Key 或不稳定在线输出。

开发期真实模型观察使用显式确认的独立命令，不进入日常测试或 CI：

```bash
npm run observe:composition -- --confirm-live --output docs/observations/YYYY-MM-DD-deepseek-question-composition.md
```

该命令按产品、运营、法务三类 Golden Case 串行各调用一次 DeepSeek，不自动重试、不择优。输出一份 Markdown 人工阅读报告和一份同名 JSON 结构化报告，只保存虚构岗位、输入指纹、题目标题、来源类型／ID、warning 和统一 Rubric 结果，不保存 Key、完整 JD、完整简历、完整面经正文或原始模型响应。人工审阅应在调用结束后写入岗位相关性、深挖价值和覆盖平衡，不能用重跑替代问题记录。

需要和上一轮比较时，可增加 `--baseline <上一轮.json>` 与 `--comparison-output <对比.md>`。当前智能组题桥接会跳过模板式 JD 复述、模型复制的重复题和多焦点模型题；当两类题都存在时，最终数量差最多为 2。法务／法律／合规岗位会额外要求至少 2 道带业务冲突或约束的模型情境题，并由观察 Rubric 单独统计。

`App.tsx` 保留页面编排、面经库切换、题目选择和浏览器语音交互；持久状态与派生数据进入 `useWorkbenchController`，导入、采集、组题、DeepSeek 会话与审阅、训练转换和备份分别进入聚焦的 use-case hooks，网络请求进入 Agent Reach / DeepSeek clients，材料、题库、练习和训练历史进入独立展示组件。项目继续采用本地优先的模块化单体，不引入 Redux、Zustand、数据库或新服务。

## MVP 能力与边界

- 支持填写目标公司和岗位。
- 面经可手动粘贴、导入文本，或导入 Agent Reach 在工作台外生成的 JSON 结果。
- 本地 `npm run dev` 时可由用户主动发起“小红书深度采集”。系统以用户可编辑的起始词为第一轮，自动扩展到精确岗位、岗位族、面试、面试题和面试轮次等最多 6 组查询；至少执行 4 轮后，连续 2 轮没有新增唯一来源即判定饱和，单次最多读取 20 篇新来源，总时限约 6 分钟。
- 深度采集会按小红书笔记 ID 跨查询去重，并把当前岗位已有 URL 作为增量边界；再次采集只读取新来源。精确／模糊选项决定起始词，用户修改的词始终优先，但不会取消后续的受限自动扩展。
- 覆盖报告展示计划／已执行查询数、累计命中、唯一来源、已有跳过、新增读取、含真题来源、真题数、读取失败和停止原因，并可展开查看每轮搜索词及新增数。正文中的连续 emoji／圈号／中文编号及无问号短题继续由纯规则提取器保守识别。
- 外部来源保存标题、平台、脱敏 URL、采集时间、摘要、问题和导入方式；没有 URL 时明确显示。正文成功但零真题的来源仍保存，状态显示“已保存正文摘要，尚未识别到真题”，避免暗示完整正文已经长期保存或正文中一定没有题目。
- 每条来源同时记录题目解析器版本。旧版 `questions: []` 来源在恢复时先用已保存摘要重新识别；重复 URL 合并时保留题目和摘要更丰富的记录，同时保留旧来源 ID，避免题库引用断裂。
- 当前岗位存在零题来源时显示“重新识别真题”。点击后仍先本地解析摘要；只有摘要不足、来源为 Agent Reach 小红书链接且处于本地开发环境时，才重新读取最多 10 篇正文。完整正文只用于当次提取，不进入浏览器存储。
- 其他标签页写入或清空工作台时，当前页不会自动覆盖正在编辑的状态；页面提示用户主动“加载最新数据”或稍后处理。
- 每条面经来源同时绑定采集时的公司与岗位。页面和题库只读取当前岗位来源，其他岗位与旧版未归类来源会被保留但隔离。
- 成功采集、导入面经文件或生成题库后，会按“公司 + 岗位”自动保存为一个“我的面经库”历史条目；历史卡片显示来源数、已提取问题数和更新时间，点开后可继续查看资料或重新生成当前岗位题库。
- 支持粘贴简历，或上传 `.txt`、`.md`、`.docx` 与文字型 `.pdf`；文件在浏览器中解析为紧凑、可编辑的文字底稿，供用户核对后用于组题和回答分析，原文件不上传。
- 以本地确定性规则生成两类主类别：“简历题”和“专业 / JD 题”；简历题从高价值经历中最多选择 3 条，并为每条选择一个不同切口（指标口径、个人贡献、关键决策、约束下执行、取舍复盘或反事实判断），面经原题通过 `source_question` 来源标签归入专业 / JD 题库。简历题保留逐字 `sourceRefs` 引文；JD 相关性只在有确定性词项交集时标记，不虚构岗位匹配。
- 题库支持“全部｜简历题｜专业 / JD 题｜面经真题”筛选；面经真题只是 `source_question` 来源维度，不建立固定第三类题库。除本地规则组题外，用户可主动触发 DeepSeek 智能组题：服务端只接收当前岗位 JD、简历、本地候选题与当前岗位面经，最多返回 12 题；被精选的真题保留原文和来源，模型衍生题统一标记 `coach_generated`，不得冒充真题。衍生题引文允许 Unicode NFKC、空白和有限标点差异，但来源 ID 与岗位归属仍严格校验；单题异常会被跳过并在页面提示，只有全部题目不可用时才整批失败。
- DeepSeek 部分成功时，材料区会显示一张紧凑结果卡：先明确“已保留 N 道有效题”，再用独立标签汇总模板式 JD 题、重复题、包含多个问题的题、来源或引文无法核验的题；类别配比调整和未知质量 code 使用安全兜底。结果卡同时说明题库已经保存并提供“查看有效题目”入口，不再叠加一条内容近似的全局成功通知，也不会自动滚动离开结果。页面不直接展示服务端原始 message。
- 作答优先尝试浏览器原生 Speech Recognition，能力不可用或授权失败时保留文字输入。
- 作答后由 DeepSeek 结合题目类别、目标 JD、简历、题目来源片段与回答，按 `interview.evidence-review.v1` 给出无分数、来源可追溯的审阅；其中“岗位关联与经历佐证”是条件性检查：需要经历证明时核对是否主动使用简历 / 本轮事实，纯知识、法规、计算或假设题可标记为无需简历佐证；开源本地版允许用户在页面临时配置自己的 Key。
- 首轮审阅后只提供一条最高信息价值的追问，由用户主动选择继续或结束；完成第二次回答后自动封闭本轮并保存两轮问题、原回答与各自审阅。训练历史保存在当前浏览器，最多保留 100 条完成记录。
- 原型数据保存在 `localStorage`，当前存储键为 `xiangqian.interview-workbench.v6`；支持 JSON 导出、导入预览、确认后完整恢复和一键清除。恢复会先在内存中校验并迁移 V1–V6 备份，无效文件或浏览器写入失败不会替换当前工作台；当前 MVP 不做自动合并。
- 除用户主动触发的本地 OpenCLI 小红书只读采集和 DeepSeek 分析外，不进行后台联网任务；不创建账号、不提供后端语音转写。

## DeepSeek 证据审阅

DeepSeek 只在本地 `npm run dev` 提供的服务端桥接中调用。默认模型为 `deepseek-v4-pro`，可以通过 `DEEPSEEK_INTERVIEW_MODEL` 显式更换。开源使用者有两种配置方式：

1. 在“模拟作答”区域点击“配置自己的 Key”。Key 通过同源本机请求交给当前服务进程，只保存在内存；提交后输入框立即清空，不进入 `localStorage`、工作台 JSON 备份、日志、`.env` 或 Git。刷新页面仍可使用，停止或重启 `npm run dev` 后自动失效。
2. 维护者可以继续通过不提交 Git 的环境变量预置 Key。页面只读取配置状态和模型名，不会读取、展示或导出环境 Key。

如果两种来源同时存在，本次会话 Key 优先。用户点击“移除本次 Key”后，会自动回退到环境 Key；如果没有环境 Key，则 DeepSeek 证据审阅重新变为未配置。

面试工作台会优先读取自己的 `.env.local`，并在没有单独配置时复用上一级 JobHunter 已有的 `.env.local`，因此现有主工作台的 `DEEPSEEK_API_KEY` 无需复制。若独立运行此目录，可将 `.env.example` 复制为不提交 Git 的 `.env.local`，再填写：

```bash
DEEPSEEK_API_KEY=your_private_key
DEEPSEEK_INTERVIEW_MODEL=deepseek-v4-pro
```

修改环境变量后需要重启本地开发服务；页面填写的会话 Key 不需要重启。静态构建没有服务端密钥桥接，Key 配置入口和 DeepSeek 按钮会保持不可用。这套会话 BYOK 只面向绑定本机的单用户开源运行方式：配置接口限制 JSON 与同源浏览器请求。未来多人公开部署时必须重新设计每用户隔离与凭证加密，不能把会话 Key 注入 Vite 客户端变量，也不能在用户之间共享进程内 Key。

一次点击只提交对应动作所需的当前公司、岗位、JD、简历正文和来源材料。智能组题额外提交本地候选题及当前岗位面经；证据审阅提交当前题目、来源片段和本次回答。接口限制材料长度、单次并发和最长等待时间；上游密钥、余额、限流、繁忙、网络、超时及无效 JSON 会映射为不含上游正文的安全错误。智能组题输出须通过类别、数量、来源 ID、岗位隔离和归一化引文核验：只归一 Unicode NFKC、空白及有限标点，不放宽来源内容；某题不合格时整题跳过并返回安全警告。证据审阅仍须通过 `interview.evidence-review.v1` 的严格来源协议。结果保存在当前浏览器，API 服务端不持久化请求正文。

## 本地深度采集小红书面经

深度采集仅在本地 `npm run dev` 可用。它要求 Chrome 已打开、OpenCLI 扩展已连接，并使用用户自己已经存在的小红书会话；工作台不会读取或保存浏览器 Cookie，也不会替用户登录。静态部署没有本地进程桥接，页面会明确禁用按钮；若要部署该能力，必须另行实现具备同等输入校验、超时、频率控制和令牌清理的服务端 adapter。

一次点击对应一次有界的前台请求：依次运行最多 6 轮 `opencli xiaohongshu search QUERY -f json`，跨轮去重后再串行读取最多 20 篇新正文。连续两轮没有新增来源、达到来源上限、执行完查询计划或达到总时限都会停止。带 `xsec_token` 的 URL 只在服务端进程内即时使用，返回浏览器和写入本地面经库前会移除所有查询参数。采集不会成为后台无人值守任务，也不会执行评论、点赞、发布等写操作。

### 搜索页提示重新登录或重启

如果页面返回 `AUTH_REQUIRED`、`blocked behind a login wall`，或出现容易被误解为“需要重启 Python”的底层提示，先不要重装 Python。当前采集实际由 Node.js 版 OpenCLI 和 Chrome 扩展完成，Agent Reach 的 Python 环境只负责安装与能力路由。

可先在普通 Chrome 中手动打开小红书搜索页，确认搜索结果能正常显示，并完成页面要求的登录或验证；若刚刚连续搜索过，应停止重复点击并等待一段时间后只重试一次。`opencli doctor` 显示守护进程和扩展正常、`whoami` 显示已登录，并不保证小红书搜索页没有单独触发登录墙、验证码或风控限制。工作台不得绕过这些平台限制。

搜索范围规则：

- **精确搜索**：`公司 + 完整岗位名 + 面经`，用于优先寻找同名岗位；
- **模糊搜索**：`公司 + 岗位族 + 面经`，公司不变，岗位名确定性归并为 `AI 产品经理`、`产品运营`、`法务` 等岗位族；
- 当前不会跨公司扩展，也不会在一次点击中自动连续尝试多组关键词，避免扩大抓取范围和触发平台风控；
- 页面会显示实际提交的搜索词，用户可以继续手动调整。

### 跨岗位资料隔离

每次采集或 JSON 导入都会把来源绑定到当时的“公司 + 岗位”。切换岗位后：

- 面经列表只显示当前岗位来源；
- 生成题库只接收当前岗位来源，引擎层会再次拒绝其他岗位或无岗位归属的来源；
- 已为其他岗位保存的来源不会被删除，只会显示隔离数量；
- 题库也记录生成时的岗位，修改公司或岗位后，旧题库立即停止展示，必须为新岗位重新生成。

旧版 V1 本地数据没有岗位归属字段，系统不能可靠判断一篇帖子属于产品运营还是法务。因此升级到 V2 时，这类来源会原样保留在“旧版未归类”隔离区，但不会进入任何新题库；可能已经混合的旧题库会被清空，简历仍保留。用户应为当前岗位重新采集，不根据帖子标题自动猜测归属。

### 我的面经库

V3 在岗位资料隔离之上增加本地历史目录。一次 Agent Reach 采集成功、导入面经文件／JSON，或使用手动整理内容生成题库后，系统会自动创建或更新对应的“公司 + 岗位”面经库。重复采集同一岗位只更新原条目，不会产生重复历史卡片。

“打开面经库”只切换当前公司和岗位，并恢复该岗位已保存的面经正文与来源。题库仍遵循岗位绑定：如果浏览器当前保存的是另一个岗位生成的题库，切换后不会显示，用户可用该历史库资料重新生成。V2 中已有的已归类来源和非空草稿会在首次打开 V3 时自动补入历史目录；旧版未归类来源仍保持隔离。当前 MVP 不提供面经库改名、删除或跨设备同步，全部历史仅保存在当前浏览器并随 JSON 备份导出。

## 简历文件解析

简历解析不需要额外 CLI、MCP 或 API Key。`.docx` 通过 Mammoth 在浏览器中抽取原始文字，`.pdf` 通过 Mozilla PDF.js 逐页读取文本层；页面只把清理后的文本写入当前输入框和浏览器本地存储，不上传原始文件，也不渲染 Word 生成的 HTML。

当前边界：

- 单个文件不超过 15 MB，解析后的正文不超过 30,000 字；
- 支持现代 `.docx`，旧版 `.doc` 需要先在 Word 中另存为 `.docx`；
- 支持带可复制文本层的 PDF；扫描件、图片型 PDF 和加密 PDF 暂不解析；
- 解析完成后必须由用户核对姓名、日期、项目符号和表格顺序；
- 只有用户之后主动点击 DeepSeek 证据审阅，解析后的文字才会随当前题目、JD、题目来源片段和回答发送给 DeepSeek。

依赖依据：[Mammoth 浏览器 ArrayBuffer / raw text API](https://github.com/mwilliamson/mammoth.js)；[Mozilla PDF.js 文本读取示例](https://mozilla.github.io/pdf.js/examples/)。

## Agent Reach 导入边界

手动 JSON 导入和本地一键采集共用以下数据边界：

```json
{
  "schemaVersion": "agent-reach.interview-experience.v1",
  "target": {
    "company": "目标公司",
    "role": "目标岗位"
  },
  "sources": [
    {
      "title": "来源标题",
      "platform": "平台名称",
      "url": "https://example.com/source",
      "capturedAt": "2026-08-10T12:00:00+08:00",
      "excerpts": ["与题目相关的短摘录"],
      "questions": ["一道已从来源中整理出的面试题？"]
    }
  ]
}
```

导入器要求 `sources` 为数组，且至少有一道 `questions`。未来 provider adapter 可以继续沿用这个 JSON 边界，把 CLI 或服务端返回结果传入工作台。

## 隐私说明

仓库内只包含脱敏、虚构组合的样例履历与面经，不包含真实个人联系方式、密钥或招聘网站凭据。简历文件解析只在当前浏览器发生，原文件不发送；解析后的文字会像手动粘贴内容一样保存在当前浏览器。浏览器语音识别能力由浏览器提供，具体处理方式受所用浏览器实现与权限策略约束；因此页面不宣称语音一定完全离线。用户填写的会话 Key 只短暂存在于密码输入框，提交后由本机服务内存持有；不会进入浏览器存储或工作台导出。用户点击 DeepSeek 深度分析前，页面会明确提示本题、回答、岗位和简历正文将发送给 DeepSeek；不点击时这些内容保持在当前浏览器。
